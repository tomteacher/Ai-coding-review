## ❌ 问题

### 1. 【严重】`copy.yml` 是 `ai-review.yml` 的旧版完整拷贝，会造成重复触发与行为冲突

- **位置**：`.github/workflows/copy.yml`（整个新增文件）
- **原因**：
  - 该文件与 `ai-review.yml` 的 `name` 完全相同（都是 `AI Code Review`），GitHub Actions 中同名 workflow 会并列展示，容易混淆。
  - 它监听 `push` 到 `feature`/`dev`，而 `ai-review.yml` 监听 `pull_request`，两者会同时触发同一套审查逻辑，产生重复报告、重复 commit、重复 API 调用。
  - 它内部仍使用 `github.event.before/after` 和 `github.event.head_commit.message`，与新版脚本期望的 `pull_request.base.sha/head.sha` 不匹配，脚本会因缺少 `BEFORE_SHA/AFTER_SHA` 直接 `exit(1)`，导致该 workflow 必然失败。
  - 文件名 `copy.yml` 语义不明，明显是误提交的备份文件。
- **修改建议**：删除 `copy.yml`。若确实需要保留旧逻辑，应重命名为有意义的名称（如 `ai-review-push.yml`），修改 `name` 避免冲突，并同步更新脚本的环境变量来源。

### 2. 【严重】commit message 拼接写法错误且冗余

- **位置**：`scripts/ai-review.mjs` 第 6 步
  ```js
  execSync('git commit -m "[skip review] 生成 AI 代码审查报告 (PR #${prNumber})"'.replace('${prNumber}', prNumber))
  ```
- **原因**：
  - 外层是单引号字符串，`${prNumber}` 不会被模板字符串插值，随后用 `.replace('${prNumber}', prNumber)` 手动替换——虽然能工作，但极其反直觉，属于「先写错再打补丁」。
  - 若 `prNumber` 中含有 `$`、`&` 等字符，`String.prototype.replace` 的替换串会做特殊处理（`$&`、`$1` 等），存在注入/替换异常风险。
  - 与上方 `filePath` 使用模板字符串的写法不一致，可读性差。
- **修改建议**：直接使用模板字符串：
  ```js
  execSync(`git commit -m "[skip review] 生成 AI 代码审查报告 (PR #${prNumber})"`)
  ```

### 3. 【中】`skip_check` 步骤未加 `if` 保护，且与 workflow 层判断逻辑不一致

- **位置**：`.github/workflows/ai-review.yml` 的 `检查是否需要跳过` 步骤
- **原因**：
  - workflow 层 `if` 判断的是 **PR title** 是否含 `[skip review]`，而 `skip_check` 步骤判断的是 **最新 commit message** 是否含 `[skip review]`。两者语义不同，容易让维护者困惑「到底哪个生效」。
  - 该步骤本身没有 `if` 条件，即使 PR title 已含 `[skip review]`（此时整个 job 已被跳过，实际不会执行到），逻辑上仍存在冗余；更重要的是，如果后续有人调整 workflow 层 `if`，这里的行为会变得难以预测。
  - 注释写「二次保险」，但两次检查的对象不同，并非真正的「二次保险」。
- **修改建议**：统一判断对象（建议都用 commit message，因为脚本 push 的 commit 带 `[skip review]`），或明确注释说明「workflow 层防人工误触发，脚本层防 bot 自触发」的不同职责。

### 4. 【中】`git diff ${before}...${after}` 未做 SHA 校验，存在命令注入/异常风险

- **位置**：`scripts/ai-review.mjs` 第 1 步
- **原因**：
  - `before`/`after` 来自环境变量，虽由 GitHub 注入，但直接拼进 `execSync` 的 shell 命令中，属于不良实践。若未来有人从其他来源注入这两个变量，存在命令注入风险。
  - 更现实的问题是：`pull_request` 事件中 `base.sha` 是 base 分支的提交，`head.sha` 是 head 分支的提交，两者可能不在同一历史线上（尤其 fork PR），`...`（三点）语法在无共同祖先时会报错，当前 `try/catch` 会直接 `exit(1)`，导致 fork PR 全部失败。
- **修改建议**：
  - 使用 `execFileSync('git', ['diff', `${before}...${after}`], ...)` 避免 shell 拼接。
  - 对 fork PR 场景，考虑先 `git fetch origin ${base}` 再 diff，或改用 `git diff ${before} ${after}`（两点）并接受可能的噪声。

### 5. 【低】`truncated` 截断可能切断 diff 中间行，导致模型误判

- **位置**：`scripts/ai-review.mjs` 截断逻辑
- **原因**：`diff.slice(0, MAX_DIFF_CHARS)` 是纯字符截断，可能把某个 hunk 从中间切断，模型看到半截 diff 可能产生误判（例如把被截断的 `+` 行当成完整新增）。
- **修改建议**：截断时按 hunk（`@@ ... @@`）边界切分，或在截断处追加 `\n... (diff 已截断) ...` 明确标记，减少模型误解。

### 6. 【低】文件末尾缺少换行

- **位置**：`.github/workflows/ai-review.yml`、`.github/workflows/copy.yml`、`scripts/ai-review.mjs` 均以 `\ No newline at end of file` 结尾
- **原因**：违反 POSIX 文本文件规范，部分工具（如某些 linter、`git diff` 展示）会产生噪声。
- **修改建议**：各文件末尾补一个换行符。
