## ❌ 问题

### 1. 严重程度：高 — YAML 缩进/键名错误导致工作流失效
- **位置**：`.github/workflows/ai-review.yml` 第 4 行附近（删除 `on:` 的那处）
- **原因**：diff 中删除了内层重复的 `on:`，但顶层 `on:` 下直接跟 `push:` 的缩进关系需要确认。原代码存在 `on:` 下又嵌套 `on:` 的明显错误（`on: on: push:`），删除内层 `on:` 是修复，但需确认删除后 `push:` 与 `pull_request:` 是否仍保持同级且正确缩进。若仅删除一行而未调整缩进，`push:` 可能变成 `on:` 的值而非子键，导致触发器失效。
- **修改建议**：确认最终结构为：
  ```yaml
  on:
    push:
      branches:
        - feature
    pull_request:
      branches:
        - main
  ```
  并本地用 `yamllint` 或 `actionlint` 校验。

### 2. 严重程度：高 — 注释掉 `ref` 与 `git fetch origin main` 会破坏 diff 基准
- **位置**：`.github/workflows/ai-review.yml` checkout 步骤的 `ref`，以及「拉取 main 分支」步骤
- **原因**：
  - 注释掉 `ref: ${{ github.event.pull_request.head.ref }}` 后，`actions/checkout` 默认检出的是触发事件的 ref。对于 `push` 事件是分支头，尚可；但对于 `pull_request` 事件默认检出的是 **merge commit**，后续若脚本依赖 `git diff origin/main...HEAD` 或向 PR 分支 push 报告，行为会与注释所述「检出 PR 分支本身」不符，可能 push 失败或 diff 结果错误。
  - 注释掉 `git fetch origin main` 后，若 `scripts/ai-review.mjs` 中仍以 `origin/main` 作为 diff 基准（`fetch-depth: 0` 只保证历史完整，不保证存在 `origin/main` 远程跟踪引用），`git diff origin/main...HEAD` 会报 `unknown revision` 而失败。
- **修改建议**：二选一：
  - 若确实要改为纯 push 触发（去掉 `pull_request`），则同步删除 `pull_request` 触发器，并保留 `git fetch origin main`（或改为 `git fetch origin main:refs/remotes/origin/main`）以保证 diff 基准存在；
  - 若仍保留 PR 触发，则恢复 `ref` 与 `git fetch origin main`，不要注释。

### 3. 严重程度：中 — 报告字段变更未同步脚本其余引用
- **位置**：`scripts/ai-review.mjs` 第 72 行 `- 提交: ${shortCommit}`
- **原因**：仅替换了展示字段，但需确认 `prNumber` 变量是否在文件其他地方仍被使用（如用于 PR 评论、push 回写、日志）。若 `prNumber` 变为未使用变量，属于死代码；若仍被使用但报告不再展示，信息不一致。
- **修改建议**：全局搜索 `prNumber`，若不再使用则删除其定义与相关逻辑；若仍用于其他用途，保留并在报告中同时展示 `提交` 与 `PR`（若存在）更利于追溯。

### 4. 严重程度：低 — 注释掉的代码应清理或加说明
- **位置**：`.github/workflows/ai-review.yml` 中被注释的 `ref` 与 `git fetch origin main`
- **原因**：注释掉的配置长期留存会造成维护困惑，且与上方注释「检出 PR 分支本身」自相矛盾。
- **修改建议**：若为临时调试，加 `# TODO:` 说明恢复条件；若为永久移除，直接删除而非注释。
