## ❌ 问题

### 1. 严重程度：高 — `HelloWorld.vue` 新增了语法错误的 `<script>` 块
- **位置**：`src/components/HelloWorld.vue` 文件末尾新增的 3 行
- **原因**：
  - 标签拼写错误：`</scrt>` 应为 `</script>`，这是明确的语法错误，会导致 SFC 编译失败。
  - 该 `<script>` 块为空且与已有的 `<script setup>` 重复，属于无意义改动。
- **修改建议**：直接删除这三行新增代码；若确需普通 `<script>` 块，应修正为 `</script>` 并补充实际内容。

### 2. 严重程度：高 — workflow 的 `if` 条件引用了 `pull_request` 事件中不存在的字段
- **位置**：`.github/workflows/ai-review.yml` 第 15 行 `if: ${{ !contains(github.event.head_commit.message, '[skip review]') }}`
- **原因**：`pull_request` 事件 payload 中没有 `head_commit` 字段（该字段属于 `push` 事件），表达式会求值为 `contains(null, ...)`，防死循环的 `if` 实际不生效，脚本提交报告后会再次触发 workflow。
- **修改建议**：改为 `github.event.pull_request.head.commit.message`，或在脚本内判断最新 commit message 是否包含 `[skip review]`。

### 3. 严重程度：高 — `git push` 在 fork PR 与并发场景下会失败
- **位置**：`scripts/ai-review.mjs` 第 6 步 `execSync('git push')`
- **原因**：
  - fork PR 场景下 `GITHUB_TOKEN` 为只读，`git push` 必然失败，导致整个 job 挂掉。
  - 审查期间若 PR 分支有新提交，`git push` 会因非 fast-forward 被拒绝，即使审查本身通过也会失败。
- **修改建议**：
  - 在 job 的 `if` 中增加 `github.event.pull_request.head.repo.full_name == github.repository` 限制仅同仓库 PR 生效。
  - push 前 `git pull --rebase`，或使用 `--force-with-lease` 并对失败做 `try/catch` 降级为告警。

### 4. 严重程度：中 — `data.choices[0].message.content` 未做防御
- **位置**：`scripts/ai-review.mjs` 第 3 步之后
- **原因**：若 API 返回结构异常（`choices` 为空、被内容过滤），会抛 `TypeError`，错误信息不友好且难以排查。
- **修改建议**：使用可选链并兜底，例如 `const review = data?.choices?.[0]?.message?.content; if (!review) { console.error('❌ 审查结果为空', JSON.stringify(data)); process.exit(1) }`。

### 5. 严重程度：低 — 文件末尾缺少换行
- **位置**：`.github/workflows/ai-review.yml` 与 `scripts/ai-review.mjs` 末尾
- **原因**：diff 显示 `\ No newline at end of file`，不符合多数项目的 lint 规范。
- **修改建议**：补上末尾换行。
